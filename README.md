Sprint 6 — UI-тесты сервиса «Яндекс Самокат»

Проект автоматизированного UI-тестирования учебного сервиса аренды самокатов
«Яндекс Самокат».

Что тестируется

Проверяются ключевые пользовательские сценарии веб-приложения:

- оформление заказа через две разные кнопки «Заказать»;
- заполнение обеих страниц формы заказа;
- выбор даты, срока аренды и цвета самоката;
- подтверждение заказа и появление сообщения об успешном оформлении;
- раскрытие вопросов FAQ и соответствие текстов ответов;
- переход на главную страницу по логотипу «Самокат»;
- открытие Dzen в новой вкладке по логотипу «Яндекс».

Тестовый стенд: <https://qa-scooter.praktikum-services.ru/>

Стек

- Python 3;
- pytest;
- Selenium WebDriver;
- Firefox;
- Page Object Model;
- Allure Framework.

Виды тестов

- UI end-to-end тесты;
- функциональные тесты оформления заказа;
- тесты навигации и внешних переходов;
- параметризованные проверки FAQ;
- позитивные сценарии работы интерфейса.

Покрытые сценарии

 Позитивные

- оформление заказа через кнопку в шапке страницы;
- оформление заказа через кнопку в центре страницы;
- оформление двух заказов с разными наборами пользовательских данных;
- заполнение адреса с выбором станции метро;
- выбор даты и продолжительности аренды;
- выбор цвета самоката и добавление комментария;
- подтверждение заказа и отображение окна успешного оформления;
- раскрытие каждого из восьми вопросов FAQ с проверкой точного текста ответа;
- переход с формы заказа на главную страницу по логотипу «Самокат»;
- переход на Dzen по логотипу «Яндекс» с переключением на новую вкладку.

 Негативные

Отдельные негативные сценарии и проверки валидации формы в текущем наборе
не реализованы. Проект сосредоточен на основных успешных пользовательских
потоках, навигации и соответствии FAQ.

 Page Object, фикстуры и параметризация

Проект построен по Page Object Model:

- `BasePage` содержит общие действия с браузером, ожидания и переключение окон;
- `MainPage` описывает главную страницу, FAQ, кнопки заказа и логотипы;
- `OrderPage` инкапсулирует заполнение и подтверждение формы заказа;
- локаторы страниц разделены на классы в `locators.py`;
- тесты содержат сценарии и проверки, а детали взаимодействия находятся в
  Page Object.

Фикстура `driver` в `conftest.py` создаёт Firefox перед каждым тестом и
гарантированно закрывает браузер после выполнения.

Параметризация используется:

- для проверки двух точек входа в оформление заказа и двух наборов данных;
- для проверки восьми пар «вопрос — ожидаемый ответ» в FAQ.

Шаги Page Object и тестовые сценарии размечены декораторами Allure.
